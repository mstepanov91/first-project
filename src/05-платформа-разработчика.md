# 05. Платформа разработчика Figma

> Источники — в [`06-источники.md`](./06-источники.md). Анализ по официальной dev-документации
> ([developers.figma.com](https://developers.figma.com/)).

Figma предоставляет несколько интерфейсов расширения: **Plugin API**, **Widget API** и
**REST API** — они позволяют расширять Figma для себя, команды и всего сообщества
([Compare the Figma APIs](https://developers.figma.com/compare-apis/)).

## 5.1. Plugin API

- Исполняется **внутри редактора Figma** (in-editor), даёт плагину доступ к графу сцены:
  чтение/создание/изменение узлов, стилей, переменных, выделения, экспорт.
- Технически: код плагина выполняется в изолированной среде (sandbox), UI плагина — в iframe;
  общение с документом — через предоставляемый API (без прямого доступа к проприетарному ядру).
- Применение: генераторы, импортеры/экспортеры, синхронизация токенов, автоматизация рутины.

## 5.2. Widget API

- Расширяет в первую очередь **FigJam** (и холст) **интерактивными виджетами**, которые видят
  и используют все участники файла (в отличие от плагина, который работает у одного
  пользователя).
- Применение: голосовалки, таймеры, канбан-карточки, мини-приложения на доске.

## 5.3. REST API

- Построен по **REST**; запросы — по HTTP-эндпоинтам с понятными функциями и кодами ответов
  ([REST API Introduction](https://developers.figma.com/docs/rest-api/)).
- Возможности (основное): получить структуру файла (узлы/дерево), изображения/рендеры узлов,
  стили и компоненты, комментарии, версии, данные команды/проекта.
- Read-ориентирован для содержимого файлов (полноценное редактирование документа делается
  через Plugin API внутри редактора).

### Variables endpoints
Отдельные эндпоинты для **переменных (Variables)**: чтение и публикация коллекций переменных,
их режимов и значений — для синхронизации дизайн-токенов с кодом/внешними системами
([Help: Variables in Dev Mode](https://help.figma.com/hc/en-us/articles/27882809912471-Variables-in-Dev-Mode)).
Часть Variables-функций REST доступна на enterprise-тарифах.

## 5.4. Webhooks V2

**Webhooks V2** позволяют наблюдать события в файлах и строить интеграции
([Webhooks V2](https://developers.figma.com/docs/rest-api/webhooks/)):

- При создании вебхука указывается **контекст (context)** и id: **team**, **project** или
  **file** — то есть можно подписаться на события конкретного файла/проекта, а не только на
  уровне команды
  ([Webhooks endpoints](https://developers.figma.com/docs/rest-api/webhooks-endpoints/)).
- Примеры событий (event types): **новый комментарий** в файле, **добавление версии** в историю
  файла, обновление/удаление файла, события библиотеки
  ([Webhooks types](https://developers.figma.com/docs/rest-api/webhooks-types/)).
- Доставка — HTTP POST на endpoint потребителя с подписью/секретом для верификации.

## 5.5. Аутентификация

Два основных способа ([Authentication](https://developers.figma.com/docs/rest-api/authentication/)):

- **Personal access token** — для индивидуальных разработчиков и скриптов.
- **OAuth2** — для приложений, действующих от имени пользователя (со скоупами/scopes).
- Некоторые части REST API (например, Activity Logs, Discovery) требуют именно **OAuth-приложения**.

## 5.6. Экосистема Community и плагины

- **Figma Community** — площадка публикации плагинов, виджетов, файлов-шаблонов, UI-китов и
  дизайн-систем.
- По публичным оценкам, в экосистеме **5000+ плагинов** — это значимый ров (moat) Figma:
  интеграции с системами токенов, аналитикой, контентом, локализацией, доступностью.

> **Выводы для нашего продукта.** Чтобы привлечь миграцию (ADR-1), важны:
> 1. **Plugin API** с доступом к графу сцены — заложить расширяемость с раннего этапа;
> 2. **REST API** на чтение структуры файла + рендеры узлов (CI, интеграции, экспорт);
> 3. **Webhooks** с контекстами file/project/team (комментарии, версии) — для интеграций с
>    локальными мессенджерами/таск-трекерами;
> 4. **Variables endpoints** — синхронизация токенов с кодом;
> 5. совместимость моделей расширения с привычками экс-пользователей Figma снижает стоимость
>    перехода.
